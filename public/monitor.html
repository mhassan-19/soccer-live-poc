Matches being measured

Event delay can only be timed on matches the server checks at a steady interval. Open a match on the main page and choose "Start measuring". A shorter interval gives finer timing but uses more of your API quota.

Response time

Time from sending a request to receiving the full response. Waiting in our own one-request-per-second queue is not counted.

Event delay

For each new goal, card, substitution or VAR event, this is the gap between the timestamp Sportradar gives the event and the moment we first saw it. It reflects delay inside Sportradar's pipeline plus up to one polling interval.

The "best case" figure subtracts the polling gap, so the true delay lies between the best case and the observed value. Sportradar's timestamp is their own clock, not the moment the ball crossed the line. To measure real-world delay, note the time you see a goal on a broadcast and compare it with the "seen at" time in the downloaded log.

Data consistency

Automatic checks that the feed agrees with itself. These catch contradictions, not facts that are wrong everywhere, so they show whether the data is internally reliable rather than proving it matches reality.
